Hovercard Pattern: popover + @media (hover: none)

This demonstrates hovercards that work on both desktop (hover to show) and touch devices (tap ⓘ to show), using only existing web platform primitives. No interesttarget attribute. No ::interest-button pseudo-element.

How it works

  • Desktop: Hover over a name to see the card. Move to the card to interact with it. Move away to dismiss.
  • Touch/spatial: The ⓘ button appears (via @media (hover: none)). Tap it to show the card. Tap elsewhere to dismiss.

The code

<style>
  .chip-info-btn { display: none; }
  @media (hover: none) {
    .chip-info-btn { display: inline-flex; }
  }
</style>

<span class="chip-wrap">
  <a href="/profile" class="chip"
     style="anchor-name: --pop-id"
     onmouseenter="document.getElementById('pop-id').showPopover()"
     onmouseleave="setTimeout(()=>{
       const p=document.getElementById('pop-id');
       if(!p.dataset.hovering) p.hidePopover()
     }, 100)">
    Alice Chen
  </a>
  <button class="chip-info-btn"
          popovertarget="pop-id"
          aria-label="Show profile">ⓘ</button>
  <div id="pop-id" popover
       style="position-anchor: --pop-id"
       onmouseenter="this.dataset.hovering='true'"
       onmouseleave="this.hidePopover();
                     delete this.dataset.hovering">
    <!-- card content -->
  </div>
</span>

Key points: The <button> is a real HTML element (focusable, in the a11y tree, standard behavior). It's conditionally shown only on non-hover devices. The popover attribute handles light-dismiss. Anchor positioning handles placement. No new web platform features required.
